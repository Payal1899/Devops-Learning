Now to fix IP part: Ingress-Reverse proxy
Browser sends HTTP/HTTPS request → request reaches the Ingress Controller → controller examines the host/path → chooses the appropriate Kubernetes Service → Service sends traffic to the appropriate Pod(s).

Http req:

Host: shop.example.com
||
Ingress: 
Host: shop.example.com
Path: /products
||
shop.example.com  →  shop-service
blog.example.com  →  blog-service

Hosting app by implementing Reverse proxy
when you run the app.py and do ctrl C it stops working, so to keep it running in background use nohup (linux utility)
it takes output from command and puts in file
nohup python3 app.py &
"&" for keeping it in background, next we run sudo lsof -i -P -n | grep LISTEN to see all running apps and we see our app still running
to kill it>>kill -9 pid 
check nohup.out for logs>>cat nohup.out

cat default from path /etc/nginx/sites-enabled
created below file as Course

# Virtual Host configuration for example.com
#
# You can move that to a different file under sites-available/ and symlink that
# to sites-enabled/ to enable it.
#
server {
       listen 80;
       listen [::]:80;

       server_name payal.com;

       root /var/www/example.com;
       index index.html;

       location / {
               proxy_pass http://localhost:6001;
       }
}

this is default syntax for nginx
now in dns add A record for aws instace ip address named payal.com(not possible on local machine as need to own payal.com domain in dns)
now if you put payal.com in Browser it shows nginx default page
before that do sudo systemctl reload nginx 
cd ~
now if you want to do same for frontend 
nohup python3 frontend.py &
cd /etc/ngnix/sites-enabled
sudo vim Course
add the content at the end

server {
       listen 80;
       listen [::]:80;

       server_name front.payal.com;

       root /var/www/example.com;
       index index.html;

       location / {
               proxy_pass http://localhost:9000;
       }
}

now go to dns>payal.com>add A record front.payal.com with same aws EC2 instance ip

reload ngnix
now if we put front.payal.com it goes to frontend cause the Reverse proxy is working through port 80 which is added in inbound rule
no need to add 9000 port in inbound rule
